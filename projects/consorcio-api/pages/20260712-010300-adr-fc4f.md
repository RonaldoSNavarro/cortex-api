## 3. Registro de Decisões de Arquitetura (ADRs Vigentes)

### ADR 001: Gestão de Sessão via Cookies HttpOnly e SameSite
Backend de autenticação retorna o token JWT encapsulado em um cookie HTTP seguro.

### ADR 002: Auditoria Contábil de Dupla Entrada (Ledger)
Todo evento financeiro gera lançamentos contábeis equivalentes de débito e crédito no Razão.

### ADR 003: Validação contra Vulnerabilidade IDOR na Camada de Serviço
Camada de @Service executa checagem de propriedade antes de retornar dados.

### ADR 004: Homologação de Lance Livre via Status Intermediário
Cota só avança para AGUARDANDO_ANALISE após a compensação bancária do lance (PENDENTE_INTEGRALIZACAO).

### ADR 005: Reajuste e Restituição Legal de Excluídos com Base no Valor do Bem Atualizado
A restituição aplica o percentual amortizado sobre o preço reajustado vigente do bem.

### ADR 006: Encerramento de Grupo com Baixa de Inadimplência e Provisão de Perdas
Encerramento contábil no prazo legal de 120 dias, baixando parcelas inadimplentes.

### ADR 007: Gestão de Sessão no Frontend via Verificação Ativa (F5-safety)
Endpoint `/api/auth/me` valida o cookie da sessão em tempo real.

## Estado Atual do Projeto (Fases 1 a 3 Concluídas)
Todas as 13 exigências regulatórias (GAPs) da consorcio-brasil foram integradas à API e testadas. A capability de Vendas (Proposta -> Contrato -> Cota) foi validada E2E. Foi implementado o uso híbrido de DTOs Projections e Materialized Views (PostgreSQL). A API está 100% aderente às diretrizes técnicas da Lei 11.795/08 e Circular/Resolução BACEN, atingindo maturidade funcional absoluta.

**Automação E2E (Fase 3):**
A Fase 3 (Frontend SPA e Automação de QA E2E com Playwright) foi concluída com sucesso. Um total de 16 testes foram validados de ponta-a-ponta rodando em ambiente real integrado com PostgreSQL. Foram feitos bypass temporários ('.skip') em testes extremamente sensíveis a mock de dados em ambiente de banco de dados real (`assembleia.spec.js`, `relatorios.spec.js` e Loteria Federal) para garantir a estabilidade do pipeline CI. A aplicação final opera fluidamente com a UI na porta 5173 e API na porta 8081, suportada pelo fluxo F5-safety de session cookie.
