# Decisões Arquiteturais (ADRs)

### ADR-001 — Extração de dados do CT-e PDF
*   **Decisão:** MVP usa interface com formulário manual, com extração parcial automatizada (chave de acesso com 44 dígitos extraída via regex com Apache PDFBox).
*   **Justificativa:** Layouts variam muito, preenchimento manual garante que a operação não trave por erro de parsing.

### ADR-002 — Armazenamento de PDFs
*   **Decisão:** Uso do sistema de arquivos local do host ou container Docker, utilizando UUIDs.
*   **Justificativa:** Opção mais simples para o MVP. O `FileStorageService` deve ser abstrato para permitir migração para nuvem (S3/MinIO) no futuro.

### ADR-003 — Optimistic Locking para eventos financeiros
*   **Decisão:** Implementação de optimistic locking nas entidades de controle de pagamento usando coluna `versao` marcada com `@Version` do JPA.
*   **Justificativa:** Previne race conditions e duplo-submit sem travas pessismistas no banco.

### ADR-004 — Acesso em Rede Local (LAN) para Uso Residencial
*   **Decisão:** Utilizar porta padrão mapeada `8080:8080` vinculada a `0.0.0.0`.
*   **Justificativa:** Permite testes e validação integrada na rede local (LAN).
